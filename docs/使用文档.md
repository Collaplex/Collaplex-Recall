# Collaplex Recall 使用文档

本地优先笔记系统 v0。笔记是人写的权威原文，由 git 管；模型对笔记库只读，
检索结果带 `[n]` 引用；记忆是模型/程序异步攒的派生数据，可审可删。

- 设计文档：`docs/diagrams/笔记软件原理.drawio`、`docs/diagrams/架构总览.svg`
- 架构图：`docs/diagrams/`（drawio 源文件 + SVG 导出）
- 实现对照：`docs/设计对照-2026-11-18.md`

---

## 1. 五分钟跑起来

安装版：

```bash
./scripts/install.sh          # 默认装到 ~/.local
recall tui                    # 任意目录可用
```

安装内容：`~/.local/bin/recall`（wrapper）、`~/.local/lib/collaplex-recall/`
（二进制 + 启动脚本）、`~/.local/share/collaplex-recall/logs/`（日志）。
重装或升级后重跑 install 脚本。

源码目录直接跑：

```bash
cd Collaplex-Recall

# 1) 起模型服务（三个终端，或 nohup）
./scripts/start-embed-server.sh   # 8081，嵌入
./scripts/start-chat-server.sh    # 8082，聊天/判题/选材/校验/提炼
./scripts/start-rerank-server.sh  # 8083，可选精排

# 2) 建库（PostgreSQL 需已在跑）
cargo run -- init

# 3) 导入 Markdown 笔记
NOTE_EMBED=http \
NOTE_EMBED_URL=http://127.0.0.1:8081/v1 \
NOTE_EMBED_MODEL=Qwen3-Embedding-0.6B \
NOTE_EMBED_DIM=1024 \
NOTE_EMBED_QUERY_PREFIX=$'Instruct: Given a user question, retrieve relevant note passages that answer it\nQuery: ' \
cargo run -- ingest ~/你的笔记目录

# 4) 起 TUI（已内置上述环境变量默认值）
./scripts/tui.sh
```

没有嵌入模型也能跑：不设 `NOTE_EMBED` 时用离线哈希向量，检索质量差但全链路可通。
没有聊天模型时，TUI 只能做 `/search`、`/stats` 这类本地命令，问答会报错。

## 2. 环境依赖

| 依赖 | 版本/位置 | 说明 |
|---|---|---|
| PostgreSQL | 18，实例数据目录 `/pgdata` | 只走 unix socket，TCP 在 pg_hba 里 reject |
| pgvector | 0.8.1 | `embeddings.vec` 用 `vector` 类型 |
| Rust | stable 1.99+ | 项目 `collaplex-recall`，二进制 `recall` |
| llama.cpp | `/tools/llama.cpp-prism/.../llama-server` | 嵌入/聊天/rerank 三个进程 |
| Qwen3-Embedding-0.6B | `~/models/Qwen/Qwen3-Embedding-0.6B-GGUF/` | Q8_0，1024 维 |
| Qwen3-VL-8B-Instruct | `~/models/lmstudio-community/Qwen3-VL-8B-Instruct-GGUF/` | Q4_K_M，文本聊天也用这个 |
| bge-reranker-v2-m3（可选） | `~/models/gpustack/bge-reranker-v2-m3-GGUF/` | Q4_K_M，交叉编码器 |

默认数据库连接：

```
host=/pgdata/socket user= dbname=note_rs
```

用 `psql -h /pgdata/socket -U "" -d note_rs` 可直接检查。

### 三个模型服务

| 端口 | 脚本 | 模型 | 备注 |
|---|---|---|---|
| 8081 | `start-embed-server.sh` | Qwen3-Embedding-0.6B | 约 1.3 GB 显存 |
| 8082 | `start-chat-server.sh` | Qwen3-VL-8B Q4 | `--no-kv-offload`，KV 放内存，约 5 GB |
| 8083 | `start-rerank-server.sh` | bge-reranker-v2-m3 Q4 | `--reranking`，约 0.4 GB |

三个同时跑约 7 GB / 8 GB。显存不够时：

- 精排不需要就不启动；要用但 OOM，设 `RERANK_NGL=0` 走 CPU
- 聊天 `CHAT_CTX` 降低（默认 4096）
- 嵌入和聊天必须同时在，因为 TUI 的检索和问答都会用

检查服务：

```bash
curl -s http://127.0.0.1:8081/health     # {"status":"ok"}
curl -s http://127.0.0.1:8082/health
curl -s http://127.0.0.1:8083/health
```

### 自检与看门狗

```bash
# 一次性自检：PG / 嵌入 / 聊天，掉了就拉起
recall supervise

# 连同精排一起
recall supervise --rerank

# 常驻看门狗，每 30 秒检查一次
recall supervise --watch --interval 30 --rerank
./scripts/supervise.sh --rerank        # 同上，自动带好默认环境变量
```

- TUI 启动时也会先跑一次自检（`NOTE_SELFCHECK=off` 可关）
- 只拉起**本机**组件；`NOTE_EMBED_URL` / `NOTE_CHAT_URL` 指向远端时不会在本机起进程
- 端口有监听但 `/health` 不是 200/503 时按“被占用”处理，不会盲目再起一个
- 服务日志：`data/logs/{embed,chat,rerank}-server.log`
- 自检日志：`data/logs/supervisor.log`，四段式：

```
[2026-11-19 10:59:48] [INFO] [检查 PostgreSQL] [连接正常]
[2026-11-19 10:59:48] [WARN] [检查 嵌入服务] [未运行 :8081]
[2026-11-19 10:59:50] [INFO] [等待 嵌入服务] [健康 2.0s]
[2026-11-19 10:59:58] [INFO] [自检结束] [全部就绪]
```

格式固定为 `[时间] [级别] [动作] [结果]`，超过 2 MB 轮转为 `supervisor.log.1`。

### 退出顺序

`/quit`（或空闲时 Ctrl-C）在退出 TUI 后按 **精排 → 聊天 → 嵌入** 的顺序关闭本机模型组件：
先 SIGTERM，单组件 10 秒未退再 SIGKILL；PostgreSQL 不动。`NOTE_QUIT_SHUTDOWN=off` 可以只退 TUI。

如果看门狗正在跑，它会在下个周期把服务重新拉起来——要么先停看门狗，要么关掉这个行为。

## 3. 初始化与导入

### 建库

```bash
cargo run -- init
```

会创建扩展 `vector` 和表：`notes / chunks / chunk_terms / embeddings / aliases /
memories / memory_edges / experiences / memory_deltas / feedback / proposals / settings`。

### 导入 Markdown

```bash
cargo run -- ingest ~/notes --repo ~/notes
```

- 递归找 `.md`，跳过隐藏目录（`.git`、`.obsidian` 等）
- 按标题/空行切块，单块默认最多 1200 字符
- `--repo` 用于记录 git HEAD（provenance 占位），不传就用笔记目录
- 内容哈希没变且当前模型向量存在 → 跳过
- 内容变了 → **chunk 级增量**：相同 `chunk_hash` 的块保留 id 和向量，只重嵌新增/变化块
- 结束时把 `notes_root` 和 `last_commit` 写进 `settings`

### 批量导入 JSONL（评测语料）

```bash
cargo run -- ingest-jsonl corpus.jsonl --prefix bench
```

每行 `{"id":"...","text":"..."}`，笔记路径记成 `bench/<id>`。用于 DuRetrieval 这类
没有 Markdown 文件的语料。

### 看状态

```bash
cargo run -- stats
```

输出笔记数、块数、向量数，以及每个嵌入模型的维度和数量。

## 4. TUI

```bash
./scripts/tui.sh
```

脚本默认：

- 嵌入：`Qwen3-Embedding-0.6B` @ 8081，1024 维，查询带 note 检索 instruction
- 聊天：`local-chat` @ 8082，4096 ctx
- `NOTE_REWRITE=on`、`NOTE_SELECT=on`、`NOTE_CONTEXT_BUDGET=2000`
- 精排默认关（`NOTE_RERANK` 未设）；校验默认开

### 界面

启动后先显示一段 Python REPL 风格的 banner：

```
recall 0.1.0 (2026-11-19) [Rust + PostgreSQL 18/pgvector] on linux
embedding: Qwen3-Embedding-0.6B | chat: local-chat
Type "/help" for commands, "/quit" to exit.
======================================================================
```

`=` 行按当前终端宽度生成，下面是滚动输出区和 `>>>` 输入提示符：

```
======================================================================
recall 0.1.0 ...                       ← 滚动输出区
...回答、来源、警告...
>>> 输入行
[状态详情]                            ← 状态区，ASCII 组合
[KV 进度条]
```

按键：

| 键 | 作用 |
|---|---|
| Enter | 提交；在别名反问中为空则跳过 |
| Backspace / Delete | 删除 |
| ← → / Home / End | 移动光标 |
| PageUp / PageDown | 回看输出 |
| 鼠标事件 | 交还终端、不再捕获；选中文字和滚轮按终端默认行为，PageUp/PageDown 始终可用 |
| ↑ / ↓ | 命令菜单打开时选择，否则上下滚动一行 |
| Ctrl-C | 有任务时中断；空闲时退出 |
| Ctrl-L | 清屏 |

### 状态行

生成期间：

状态区**常驻**，只有一行：详情 + 两根方块进度条。

```
[完成 3.9s] | [69 token]  KV [███▌        ] 695/4,096 | 上下文 [████        ] 460/2,000
```

- **KV**：本次生成时 llama.cpp 的 KV cache 用量 / 上下文窗口
- **上下文**：本轮检索进 prompt 的上下文 token / `NOTE_CONTEXT_BUDGET`
- 两根条的宽度按终端剩余空间自动分配
- 生成结束后不消失：状态停在 `[完成 …]`，两根条都保留最后比例
- 空闲时两根都显示空条和 `--`
- 首 token、cache、prompt 明细不占状态行，完成行里仍有
- 整体只用白/灰：填充白、空白深灰，菜单选中行用反色，不再使用彩色

- `思考中` 在第一个 token 前，之后是 `生成中`
- token 是流式增量估算，结束时以服务端 `usage` 校正
- `cache` 来自 llama-server `/slots` 的 `n_prompt_tokens_cache`
- KV 用量 = prompt + 已生成，对比 `n_ctx`

阶段会显示在状态行：`判题中…`、`检索中…`、`选材中…`、`生成中…`、
`分批 1/4`、`整合分批答案`、`学习别名…`、`记录反馈…`。

### 直接提问

输入问题回车即可。一轮的流水线：

1. **判题改写**：模型输出 `query / intent / entities / unknown`（≤120 token、3 s 超时）
2. **别名展开**：问题里包含别名就追加实体；有未知简称会先反问
3. **记忆检索**：词项匹配 + 图一跳，只取 active 记忆
4. **检索**：向量 + 两段式 BM25（α 默认 0.05），可选交叉编码器精排
5. **选材**：模型从 20 个候选里选，少于 2 条回退检索前 6
6. **分批生成**：选中片段全部保留；超过预算就分多批作答，最后整合
7. **校验 / 拒答**：检查引用编号 + 模型判断引用是否支撑答案
8. **回填指针**：更新上轮命中，供下一轮指代
9. **后台提炼**：按 `NOTE_EXTRACT_MODE` 立即/每 N 轮/空闲提炼记忆、别名、经验

回答后面会列出来源 `[n] path › heading`，以及完成耗时、token、上下文用量。

### Markdown 渲染

回答是一次性整段返回的，所以不做流式渲染，而是在答案到达后统一渲染：

- 标题去掉 `#`，白色加粗
- `**粗体**`、`*斜体*`、`` `行内代码` ``
- `-` / `*` / `+` 列表显示为 `•`
- `>` 引用加 `│ ` 前缀
- ``` 代码块用 `┌ 语言` / `│` / `└────────` 包裹
- `[文字](url)` 显示为 `文字 (url)`
- `---` 分隔线显示为一条横线

配色仍然只有白/灰，代码块和行内代码用深灰背景区分。

### 命令菜单

输入 `/` 会自动列出全部命令和说明；继续输入会按命令名过滤：

```
/search         只检索，看两路名次和分数
/stats          索引概况

- `↑` / `↓` 选择，`Tab` 补全
- 输入未完整的命令时，`Enter` 先补全；再按一次才执行
- 例如输入 `/sea`，菜单只剩 `/search`，`Tab` 得到 `/search `

| `/alias add 词 = 实体 [--force]` | 学别名 |

| `/memory reextract` | 失效记忆按当前 chunk 重新绑定 |
| `/experience add 规则` / `list` / `promote 编号` / `reject 编号` | 经验管理 |
| `/adopt`（`/good`） | 上一轮答案有用；给匹配到的候选经验 +1 |
| `/reject 原因`（`/bad`） | 上一轮答案不对；记忆边 LTD、候选经验 -1 |

| `/proposals` | 待处理提案 |
| `/apply 编号` | 写文件（唯一修改笔记的路径；校验 base_hash） |
| `/discard 编号` | 拒绝提案 |
| `/clear` / `/help` / `/quit` | 清屏/帮助/退出（退出时按顺序关闭模型组件） |

### 别名与反问

- 检索前自动展开；命中的别名会显示 `别名：断网 → 掉线`
- 判题输出 `unknown` 且别名表未命中时，TUI 会停住：
  `别名未命中：小破机`，状态行提示输入实体
- 输入实体回车 → 写入别名表 → 自动重跑原问题；空回车跳过
- 同一别名指向不同实体默认拒绝，`/alias add ... --force` 覆盖

### 记忆

```text
/memory add 校园网认证排查.md = 校园网约61分钟掉线一次 --pin
/memory list
/memory check
/memory reextract
/memory rm 2
```

- 记忆绑定来源笔记，记录 `commit_hash / content_hash`；可再绑定 chunk
- 读取前 `refresh`：来源笔记或 chunk 变了 → 未固定记忆标 `stale`，不参与检索
- `--pin` 的记忆不会自动降级
- 软删除只改状态
- `reextract` 在当前笔记里找词项覆盖 ≥25% 的 chunk 重新绑定；`recall memory reextract --model`
  让模型判断旧记忆是否仍成立并重写，旧条标记 `superseded`

### 经验

- 提炼器产出候选；候选只有被匹配、且你 `/adopt` 或 `/cite` 后才累计
- 累计 `NOTE_EXPERIENCE_PROMOTE_USES`（默认 3）次自动晋升；`/reject` 扣 1
- 晋升经验放在 system 之后的动态块，不破坏稳定 skill 前缀
- 命令式复核：`/experience list/promote/reject`

### 反馈

| 动作 | 记录 | 副作用 |
|---|---|---|
| `/adopt` | `adopt` | 候选经验 +1 |
| `/cite n` | `cite`，target=n | 候选经验 +1 |
| `/reject 原因` | `reject` | 记忆边 LTD；候选经验 -1 |
| `/memory rm` | `delete_memory` | 记忆边 LTD |

反馈落 `feedback` 表并写 JSONL；`recall tune` 可用这些数据重放 α。

### 收件箱与提升

```text
/note 今天想到：掉线时先看门户会话
/inbox
/promote 1 校园网认证排查.md
```

`/promote` 把条目追加到目标笔记并从收件箱移除，之后 `/ingest` 更新索引。

### 补丁提案

```text
/propose 校园网认证排查.md = 在文末追加一行“测试提案”
```

- 模型输出修改后的完整内容，程序算 unified diff，彩色显示 +/-，**不写文件**
- 目标笔记超过 12000 字会拒绝提案；先把范围缩小
- `/apply 1`：再次校验 `base_hash`，通过才原子替换文件
- 文件在提案后被改过会拒绝覆盖
- `/discard 1` 拒绝

笔记修改后运行 `/ingest`；记忆会在下次读取时按 chunk 哈希自动降级。

## 5. CLI 参考

```text
recall init
recall ingest <目录> [--repo <git目录>] [--max-chars 1200]
recall ingest-jsonl <file> [--prefix bench] [--max-chars 1200]
recall search <查询> [-k 10] [--candidates 50] [--no-vector] [--no-lexical]
     [--fusion rerank|rrf] [--alpha 0.05] [--vector-weight 1.0] [--lexical-weight 0.3]
     [--no-alias] [--json] [--verbose]
recall eval <queries.jsonl> <qrels.jsonl> [--prefix bench] [-k 10] [--candidates 100]
     [--no-vector] [--no-lexical] [--fusion ...] [--alpha ...] [--use-rerank] [--json]
recall stats
recall tui   （别名 repl）
recall alias add <词> <实体> [--force] | list [--filter] | rm <词>
recall memory add <笔记路径> <内容> [--chunk ID] [--pin] | list | rm <id> | check
     | reextract [--model] [--limit 100]
recall experience add <规则> | list | promote <id> | reject <id>
     | touch <查询>          # 模拟一次正反馈：匹配候选并 +1
recall feedback list [--limit 20]
recall delta list [--limit 20] | merge [--limit 100]
recall edges list | gc [--min 0.05] [--days 7] | sensitivity [--delta 0.1]
recall tune [--max 0.5] [--step 0.05] [--apply] [--force]
recall supervise [--watch] [--interval 30] [--rerank]
```

`search --json` 输出完整命中；`eval` 输出 recall@k / hit@k / MRR / nDCG@k。
`tune --apply` 写入 `settings.alpha`，样本不足或无区分度时拒绝，`--force` 覆盖。

## 7. 数据模型

| 表 | 内容 | 生命周期 |
|---|---|---|
| `notes` | 路径、标题、内容哈希、git commit | 随笔记 |
| `chunks` | 块正文、标题路径、块哈希、词数 | 随笔记 |
| `chunk_terms` | BM25 倒排：块 + 词项 + 词频 | 随笔记 |
| `embeddings` | 块 + 模型 + 维度 + 向量 | 随模型 |
| `aliases` | 词 → 实体（唯一、冲突检测） | 长期 |
| `memories` | 事实 + note/chunk provenance + pinned/status | 长期 |
| `memory_edges` | 记忆图边 + 权重 + 更新时间 | 长期 |
| `experiences` | 经验候选/active/rejected + 复用计数 | 长期 |
| `memory_deltas` | 提炼 pending/applied + 结果 | 审计 |
| `feedback` | 采纳/纠正/引用/删记忆 | 长期 |
| `proposals` | 补丁提案、base_hash、diff、状态 | 待审/已应用 |
| `settings` | `notes_root / last_commit / alpha` | 长期 |

### 重建

索引、chunks、terms、embeddings 都是派生数据：删表后重新 `ingest` 即可。

**记忆、经验、反馈、提案在数据库里，不在笔记文件里。** 删库会丢这些；
需要保留时先备份：

```bash
pg_dump -h /pgdata/socket -U "" note_rs > note_rs-backup.sql
```

## 8. 维护

### 笔记修改后

- TUI 启动时比较 git HEAD，变了自动 ingest
- 不是 git 仓库或想立刻更新：`/ingest 目录` 或 `recall ingest 目录`
- 只改了一篇笔记时也是整目录扫描，但未变内容会跳过；变化的笔记按 chunk 增量重嵌

### 记忆

```bash
recall memory check        # 标记 stale
recall memory reextract    # 确定性重新绑定
recall memory reextract --model   # 模型判断并重写
```

### delta / 图边

```bash
recall delta list
recall delta merge         # 补跑崩溃遗留的 pending
recall edges list
recall edges gc --min 0.05 --days 7
recall edges sensitivity --delta 0.1
```

### 校准 α

```bash
recall tune                # 只看报告
recall tune --apply        # 样本足够时写入 settings.alpha
recall tune --apply --force  # 样本不足时强制写入
```

## 10. 故障排查

| 现象 | 原因/处理 |
|---|---|
| `连接 PostgreSQL 失败` | 实例是否在跑；socket 路径 `/pgdata/socket`；`pg_isready` |
| 检索“向量 0 候选” | 嵌入前缀变了；检查 `recall stats` 里的 model_id，统一 ingest/查询前缀 |
| ingest 报嵌入失败 | 8081 是否在跑；`NOTE_EMBED_URL` 是否正确 |
| 问答报聊天服务失败 | 8082 是否在跑；模型是否 OOM |
| 精排失败 | 8083；不影响主流程，会保留原顺序 |
| 显存不足 | 不启 8083，或 `RERANK_NGL=0`；降 `CHAT_CTX` |
| cargo 拉包失败 | 全局源 `repo.lan` 可能解析不了；项目 `.cargo/config.toml` 已局部走 rsproxy |
| 提炼/判题 JSON 不符 | 模型输出漂移；可 `NOTE_REWRITE=off`、`NOTE_SELECT=off`、`NOTE_EXTRACT=off` 降级 |
| `/propose` 报 notes_root | 先对笔记目录 `ingest` 一次；或手动写 `settings.notes_root` |
| `/apply` 拒绝覆盖 | 提案后文件被改过；重新 `/propose` |
| `tune --apply` 拒绝 | 样本 <5 或无区分度；`--force` 才写 |
| TUI 花屏/键位异常 | 需要真实 TTY；退出后 `reset`；窗口别太小 |
| 记忆全部 stale | 重新 ingest 后 chunk id 变了；`memory reextract` 或接受降级 |

## 11. 边界与已知限制

- 模型对笔记库**只读**；`/apply` 是用户命令，不是模型能力
- 生成默认一次性渲染，不流式、不展示思考
- 检索是固定流水线，不是模型发起的 tool calling；没有 2~3 轮工具往返
- 交叉编码器默认关闭：真实笔记合成集上会降分，DuRetrieval 上略升
- 提炼/选材/校验都依赖模型，可能漂移或漏选；程序有兜底但不保证
- 经验晋升是**反馈事件**驱动的；没有反馈就不会晋升
- 图边冷启动弱：η=0.1、阈值 0.15，一次共引不足以触发一跳
- chunk_hash 对重新切块敏感；大改笔记后记忆会大面积降级
- 评测目前是模型合成集，人工标注 50 题仍未做

## 12. 权限铁律（不要破坏）

1. 模型对笔记库只读。工具白名单只有 `search / read / propose`，结构上没有写原语。
2. 模型对记忆库不能在线直写，只能走异步 delta；别名内联学习由用户在反问中确认后由程序写入。
3. 笔记的每一次修改都由人执行（`/apply`），git 负责记录和回滚。
4. 索引、记忆、二层表都是派生数据；坏了能重建，但 `memory / experiences / feedback /
   proposals` 目前只存在数据库里，删库前先备份。
